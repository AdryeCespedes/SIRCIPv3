## Requirement Completeness

- [x] CHK001 ¿Está especificado qué contiene y cómo se comporta la pantalla de ingreso, más allá de que FR-011 la nombre? [Gap, Spec §FR-011]
  - **No pasa**: FR-011 la enumera y FR-002 exige un motivo genérico ante el fallo, pero ningún requerimiento describe la pantalla en sí.
  - **Resuelto (2026-08-20)**: FR-013 enumera los datos que recoge cada pantalla, incluida la de ingreso: nombre de usuario y contraseña, y ninguno más.
- [x] CHK002 ¿Está definido a qué pantalla llega cada rol después de autenticarse? [Gap, Spec §FR-001, §FR-011]
  - **No pasa**: el destino tras el ingreso no está definido para ninguno de los dos roles, y el facturador y el Administrador tienen pantallas primarias distintas.
  - **Resuelto (2026-08-20)**: FR-012 define que ambos roles llegan a la pantalla de cálculo tras autenticarse, porque es la de uso diario para los dos.
- [x] CHK003 ¿Está definido cómo se navega entre las cuatro pantallas? [Gap, Spec §FR-011]
  - **No pasa**: el conjunto de pantallas está cerrado pero no hay ningún requerimiento sobre cómo se llega de una a otra.
  - **Resuelto (2026-08-20)**: FR-012 exige una navegación persistente entre las cuatro pantallas.
- [x] CHK004 ¿Está definido si el rol Usuario ve u oculta los accesos a las pantallas reservadas al Administrador? [Gap, Spec §FR-006, §FR-010]
  - **No pasa**: FR-010 deniega el acceso, pero mostrar un acceso que después deniega es a la vez mala experiencia y una filtración de la superficie administrativa.
  - **Resuelto (2026-08-20)**: FR-012 exige que la navegación liste solo las pantallas que el rol puede usar y prohíbe ofrecer acceso a una que después se denegaría, de modo que no se filtra la superficie administrativa.
- [x] CHK005 ¿Está definida la superficie desde la que el Administrador da de baja el padrón de un período? [Conflict, Gap, Spec §FR-011, §FR-034]
  - **No pasa**: FR-034 es una función reservada al Administrador y ninguna de las cuatro pantallas de FR-011 la aloja. Una función completa quedó sin superficie.
  - **Resuelto (2026-08-20)**: FR-011 asigna la baja lógica a la pantalla de historial y agrega que ninguna función puede quedar sin una de las cuatro superficies. FR-035 exige que cada constancia no dada de baja ofrezca la acción.
- [x] CHK006 ¿Está definido si la baja lógica exige una confirmación previa, siendo una acción irreversible que libera el almacenamiento? [Gap, Spec §FR-034]
  - **No pasa**: FR-034 declara la baja irreversible y con liberación inmediata del almacenamiento, y no hay ningún requerimiento de confirmación.
  - **Resuelto (2026-08-20)**: FR-034 exige una confirmación explícita que nombre el período afectado antes de ejecutar la baja, por ser irreversible y liberar el almacenamiento. El escenario 5 de la Historia 5 lo verifica.
- [x] CHK007 ¿Están especificados los campos de la pantalla de importación y cómo se ingresa la ruta del archivo? [Gap, Spec §FR-019, §FR-022]
  - **No pasa**: FR-019 define los tres datos de entrada del pedido, pero nada dice de la pantalla que los recoge.
  - **Resuelto (2026-08-20)**: FR-013 especifica los tres datos de la pantalla de importación, y que la ruta se expresa relativa al directorio de importación configurado.
- [x] CHK008 ¿Están especificados los campos de la pantalla de cálculo y su disposición? [Gap, Spec §FR-037, §FR-056]
  - **No pasa**: FR-037 define los cuatro datos de entrada y FR-056 los desenlaces, pero el formulario en sí no tiene requerimientos.
  - **Resuelto (2026-08-20)**: FR-013 especifica los cuatro datos de la pantalla de cálculo. La disposición visual queda como decisión de diseño, no de requerimiento.
- [x] CHK009 ¿Está definido cómo se le presentan al facturador los errores de datos inválidos: por campo o como un mensaje único? [Gap, Spec §FR-038, §FR-056]
  - **No pasa**: FR-038 rechaza cinco condiciones distintas de datos inválidos y ninguna tiene forma de presentación definida.
  - **Resuelto (2026-08-20)**: FR-014 exige señalar el error en el campo que lo causa cuando es atribuible, o como mensaje único cuando no, y conservar los datos ya ingresados. El escenario 8 de la Historia 3 lo verifica.
- [x] CHK010 ¿Está definido un estado de espera para el cálculo, que puede tardar hasta 2 segundos en el percentil 99? [Gap, Spec §FR-052, §FR-056]
  - **No pasa**: no hay estado de carga para el cálculo, a diferencia de la importación.
  - **Resuelto (2026-08-20)**: FR-015 exige informar que el cálculo está en curso mientras espera el resultado.
- [x] CHK011 ¿Está definido qué muestra la pantalla cuando la sesión expira o queda invalidada mientras el usuario está operando? [Gap, Spec §FR-004, §FR-009]
  - **No pasa**: FR-004 expira por inactividad y FR-009 invalida al cambiar el rol, pero ninguna dice qué ve el usuario que estaba en una pantalla cuando eso ocurre.
  - **Resuelto (2026-08-20)**: FR-016 exige informar que la sesión terminó y llevar al ingreso, y prohíbe fallar en silencio o presentar el rechazo como un error de la operación pedida.
- [x] CHK012 ¿Están especificados los rótulos con que se presenta cada tipo de percepción, dado que FR-057 exige que cada importe esté rotulado? [Gap, Spec §FR-047, §FR-057]

  - **Resuelto (2026-08-20)**: FR-017 fija los cuatro rótulos concretos: Percepción IIBB SIRCIP, Percepción por sobretasa, Percepción local y Percepción por no inscripto.

## Requirement Clarity & Measurability

- [x] CHK013 ¿Es "estados distinguibles entre sí y explícitos" verificable de forma objetiva? [Measurability, Spec §FR-056]
  - **No pasa**: la intención es clara pero la propiedad no es comprobable como está escrita. Falta decir qué debe transmitir cada estado para considerarse distinguible.
  - **Resuelto (2026-08-20)**: FR-056 pasó de "distinguibles y explícitos" a exigir que cada desenlace tenga un mensaje propio que nombre su causa, que es comprobable.
- [x] CHK014 ¿Es "individualmente seleccionable" verificable de forma objetiva? [Measurability, Spec §FR-057]
  - **Pasa**: es comprobable sin ambigüedad: se puede seleccionar un importe sin arrastrar los demás.
- [x] CHK015 ¿Está especificado el formato de presentación de importes y fechas? [Gap, Spec §FR-056, §FR-057]
  - **No pasa**: los escenarios escriben los importes como `$10,50` y `$0,51`, con coma decimal, pero ningún requerimiento lo exige. Mostrar `10.50` donde se espera `10,50` en un importe fiscal es un error de lectura con consecuencia.
  - **Resuelto (2026-08-20)**: FR-017 fija coma decimal, punto de miles, dos decimales siempre, fechas `dd/mm/aaaa` y períodos `mm/aaaa`.
- [x] CHK016 ¿Es "estado de espera explícito" verificable, o solo lo es la parte del control deshabilitado? [Measurability, Spec §FR-022]
  - **No pasa**: el control deshabilitado es comprobable; el estado de espera es cualitativo y no dice qué debe transmitir.
  - **Resuelto (2026-08-20)**: FR-022 pasó de "estado de espera explícito" a exigir que informe que la importación está en curso y que la espera puede llegar a 60 segundos. Ambas partes son comprobables.
- [x] CHK017 ¿Están especificados el orden y el contenido de cada fila de la vista del historial? [Completeness, Spec §FR-035]
  - **Pasa**: FR-035 fija el orden por fecha descendente y enumera los siete datos de cada constancia, más el estado vacío.
- [x] CHK018 ¿Es verificable que el conjunto de pantallas es cerrado, como FR-011 declara? [Measurability, Spec §FR-011]
  - **Pasa**: FR-011 las enumera con nombre y rol exigido, así que el conjunto es recorrible y la regla de FR-010 se puede auditar contra él.

## Requirement Consistency

- [x] CHK019 ¿Es consistente que FR-056 hable de "los tres desenlaces posibles" con que FR-038 defina el rechazo por datos inválidos como un cuarto desenlace de la misma pantalla? [Conflict, Spec §FR-038, §FR-056]
  - **No pasa**: son cuatro desenlaces, no tres: percepciones, ausencia de percepción, padrón inexistente y datos inválidos. El cuarto quedó fuera de la enumeración.
  - **Resuelto (2026-08-20)**: FR-056 enumera ahora los cuatro desenlaces, incorporando los datos de entrada inválidos y remitiendo a FR-014 para su presentación.
- [x] CHK020 ¿Es consistente exigir estado de espera y control deshabilitado para la importación y no exigir nada equivalente para el cálculo? [Consistency, Spec §FR-022, §FR-052]
  - **No pasa**: la asimetría puede justificarse —el cálculo no muta estado y tarda 2 segundos, no 60— pero el spec no la justifica ni la menciona.
  - **Resuelto (2026-08-20)**: FR-015 justifica la asimetría por escrito: el cálculo no modifica el estado del sistema y su espera es de hasta 2 segundos y no de hasta 60, así que informa el progreso pero no deshabilita el control.
- [x] CHK021 ¿Es consistente que FR-011 declare el conjunto de pantallas cerrado con que exista una función reservada al Administrador sin superficie asignada? [Conflict, Spec §FR-011, §FR-034]
  - **No pasa**: misma causa raíz que CHK005. El conjunto cerrado deja afuera la baja lógica.
  - **Resuelto (2026-08-20)**: FR-011 cerró el conflicto asignando la baja al historial y exigiendo que ninguna función quede sin superficie. Misma corrección que CHK005.
- [x] CHK022 ¿Es consistente que FR-057 prohíba la exportación con que SC-004 exija cero importes retipeados? [Consistency, Spec §FR-057, §SC-004]
  - **Pasa**: copiar no es exportar. FR-057 habilita la copia y prohíbe la descarga, y SC-004 mide la transcripción, no el formato de salida.
- [x] CHK023 ¿Es consistente el criterio de que un estado vacío no se confunda con una falla entre la vista del historial y la pantalla de cálculo? [Consistency, Spec §FR-035, §FR-056]
  - **Pasa**: FR-035 y FR-056 aplican el mismo criterio, cada uno en su pantalla, con la misma redacción de fondo.

## Scenario Coverage — Excepción

- [x] CHK029 ¿Está definido qué muestra la pantalla si se pierde la conexión con el servidor durante un cálculo o una importación? [Gap, Exception Flow, Spec §FR-022, §FR-056]
  - **No pasa**: no está tratado. En la importación es especialmente relevante, porque el pedido puede haber quedado corriendo del lado del servidor.
  - **Resuelto (2026-08-20)**: FR-018 exige informar que la operación no pudo confirmarse, y prohíbe presentarla como exitosa o como fallida.
- [x] CHK030 ¿Está definido qué ocurre si el Administrador abandona la pantalla de importación mientras la importación está en curso? [Gap, Spec §FR-020, §FR-022]
  - **No pasa**: la importación es sincrónica y dura hasta 60 segundos, y no hay requerimiento sobre abandonar la pantalla en el medio.
  - **Resuelto (2026-08-20)**: FR-018 define que la importación continúa hasta concluir si el Administrador abandona la pantalla, y que su resultado queda disponible en el historial.
- [x] CHK031 ¿Está definido el comportamiento cuando el mismo usuario opera el sistema desde dos pestañas a la vez? [Gap, Spec §FR-022]
  - **No pasa**: las sesiones simultáneas están excluidas explícitamente, pero dos pestañas comparten una sola sesión y el control deshabilitado de FR-022 sería por pestaña, no por período.
  - **Resuelto (2026-08-20)**: FR-018 aclara que el control deshabilitado de FR-022 opera sobre la pantalla en uso y no debe presentarse como garantía de exclusión entre pantallas o sesiones distintas.
- [x] CHK032 ¿Está definido si la vista del historial refleja las importaciones que otro Administrador realizó mientras la pantalla estaba abierta? [Gap, Spec §FR-035]
  - **No pasa**: no hay requerimiento de actualización, y el historial es un recurso compartido entre Administradores.
  - **Resuelto (2026-08-20)**: FR-035 declara que el listado no se actualiza por sí solo, que refleja el estado al abrirlo, y que el Administrador puede recargarlo sin salir de la pantalla.
